Introduction

UploadMedia is an enterprise-grade ecosystem for handling complex file upload requirements. It provides a bridge between raw multipart binary streams and high-level media management, ensuring that massive assets can be ingested safely, processed efficiently, and served reliably.

Atomic & Resumable

Switch between direct atomic uploads for small files and chunk-based resumable uploads for gigabyte-scale assets.

Intelligent Serving

Built-in support for HTTP Range requests, allowing your users to seek through 4K videos with zero configuration.

WASM Transformation

Process media directly in the browser. Trim, transcode, and resize video/audio before it ever hits your server.

Database Orchestrated

Seamlessly syncs with MongoDB or SQL to track every byte, ensuring 100% reliability in high-traffic environments.

Ready for Any Framework

We handle the plumbing, you handle the business logic. Native adapters for 8 different environments mean you can deploy anywhere.

Express Next.js Hono Fastify Elysia Koa H3 Raw Node

Getting Started

I. Framework Installation

For React, Vue, Next.js, or Express environments, install via your favorite package manager.

npm install @upload-media/client @upload-media/server

II. Vanilla CDN Resolution

For pure HTML projects, use the Unpkg CDN to resolve dependencies without local node_modules.

<!-- Add to <head> -->
<script type="importmap">
{
  "imports": {
    "@upload-media/client": "https://unpkg.com/@upload-media/client@latest/dist/index.mjs",
    "zustand/vanilla": "https://unpkg.com/zustand@latest/esm/vanilla.mjs",
    "immer": "https://unpkg.com/immer@latest/dist/immer.mjs"
  }
}
</script>

Frequently Asked Questions

How does the system handle gigabyte-scale files?

We use Chunked Orchestration. Files are sliced into 2MB-5MB parts in the browser. If a connection drops, only the current chunk is lost. The worker resumes from the last successfully acknowledged chunk stored in IndexedDB.

Are COOP/COEP headers mandatory?

Only if you enable Media Transformation (WASM). FFmpeg.wasm requires SharedArrayBuffer, which is only available in cross-origin isolated contexts. Standard uploads work without these headers.

Does this work with Cloudflare R2 or MinIO?

Yes. The S3StorageAdapter is fully compatible with any S3-compliant API. Just provide the custom endpoint and enable forcePathStyle for MinIO.

Troubleshooting

413 Payload Too Large

The server's body-parser or proxy (Nginx) is blocking the chunk.

  • Set client_max_body_size to 0 in Nginx.
  • Increase maxFieldSize in Engine config.

SharedArrayBuffer Error

Transformation fails with "SharedArrayBuffer is not defined".

  • Check Cross-Origin-Opener-Policy: same-origin
  • Check Cross-Origin-Embedder-Policy: require-corp

Manifest Sync Error

IndexedDB indicates a manifest mismatch during resume.

  • Clear browser storage and retry.
  • Ensure uploadId is unique per session.

Slow Chunk Recovery

Resuming takes too long to verify existing chunks at scale.

  • Integrate Cache: Use @mongoose-performance-cache for MongoDB repos to achieve 1000+ RPS with zero-allocation hashing.
  • Custom Hooks: Use the afterPutObject and beforeFindFiles hooks to implement Redis caching manually.
  • Pre/Post Logic: Implement pre-transform or post-save logic directly in your Database Repository or via Engine Hooks.
