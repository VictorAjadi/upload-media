Server-Side Manual

Complete guide to configuring the backend engine, framework adapters, storage providers, and database repositories.

Complete Production Example

This Express example shows the recommended end-to-end setup: dual storage, Mongoose persistence, and the background task pattern.

server.ts
import {
  UploadEngine,
  S3StorageAdapter,
  LocalDiskStorageAdapter,
  CloudinaryStorageAdapter,
  MongooseRepository,
  createExpressAdapter,
  createExpressFileServingMiddleware
} from '@upload-media/server';

// ── Storage ──────────────────────────────────────
const s3 = new S3StorageAdapter({
  bucket: 'prod-bucket',
  region: 'us-east-1',
  credentials: { accessKeyId: '...', secretAccessKey: '...' }
});

const local = new LocalDiskStorageAdapter({
  rootDir: './uploads',
  publicBaseUrl: 'http://localhost:3000/static'
});

const cloudinary = new CloudinaryStorageAdapter({
  cloudName: 'my-cloud',
  apiKey: '...',
  apiSecret: '...',
  folder: 'user_uploads'
});

// ── Database ─────────────────────────────────────
const database = new MongooseRepository({
  mongooseConnection: mongoose.connection
});

// ── Engine ────────────────────────────────────────
const engine = new UploadEngine({
  database,
  storages: { s3, local, cloudinary },
  defaultStorage: 's3',
  uploadTypes: {
    avatar: {
      allowedKinds: ['image'],
      limits: { image: 5 * 1024 * 1024 },
      storage: 'cloudinary',
      thumbnails: true
    },
    video: {
      allowedKinds: ['video'],
      limits: { video: 500 * 1024 * 1024 },
      thumbnails: true,
      quality: 'high'
    }
  }
});

// ── Route ─────────────────────────────────────────
const adapter = createExpressAdapter();

app.post('/api/upload', adapter.wrap(async (req, res) => {
  const result = await engine.handle(req, res);

  if (result.status === 'success') {
    return {
      ...result,
      onBackground: async () => {
        await notifyAnalytics(req.fileFields['video'][0].id);
      }
    };
  }
  return result;
}));

// ── File Serving ──────────────────────────────────
app.use('/stream', createExpressFileServingMiddleware('./uploads', {
  database,
  cacheMaxAge: '30d'
}));

Engine Configuration

UploadEngineConfig

Property Type Default Description
storages Record<string, StorageAdapter> - Named map of storage backends.
defaultStorage string - Key of the primary storage provider.
database MetadataRepository - Database adapter for file records.
uploadTypes Record<string, UploadTypeConfig> - Named upload context definitions.
autoRespond boolean true Auto-send JSON response on completion.
maxFieldSize number 1MB Size cap for non-file text fields.
maxFiles number 10 Max concurrent files per batch.
staleRetentionMs number 24h TTL before incomplete chunks are purged.
onUploadComplete Function - Hook fired after storage reassembly.
onError Function - Global handler for fatal exceptions.

UploadTypeConfig

Property Type Required Description
name string Yes Context ID (e.g. 'posts', 'profile').
allowedKinds MediaKind[] Yes 'image', 'video', 'audio', 'document'.
limits Record Yes Total size caps per media kind.
chunkLimits Record No Max size for individual chunks.
storage string No Override the default storage for this type.
thumbnails boolean No Enable auto thumbnail generation.
quality string No Processing profile: 'low', 'medium', 'high'. Supports images, videos, and now audio.

The 8 Framework Adapters

Every adapter exposes the same wrap() method. The engine call is always const result = await engine.handle(req, res).

1. Express.js

const adapter = createExpressAdapter();
app.post('/upload', adapter.wrap(async (req, res) => {
  const result = await engine.handle(req, res);
  return result;
}));

2. Hono (Edge)

const adapter = createHonoAdapter();
app.post('/upload', adapter.wrap(async (req, res) => {

Chunk Lifecycle

01 StagingChunks written to temp path keyed by sessionId + index.
02 VerifyFinal chunk triggers integrity check across all parts.
03 ReassembleParts concatenated (disk) or MPU completed (cloud).
04 FinalizeURL generated and record updated in the database.

Performance & Caching

For high-traffic environments, verifying thousands of chunks against a primary database can become a bottleneck. We recommend integrating a performance cache.

Smart Mongoose Caching

If using MongoDB, integrate @mongoose-performance-cache to eliminate DB contention during chunk storms.

  • 1000+ RPS: Handles massive chunk ingress without event-loop lag.
  • Smart Invalidation: Cache stays perfectly synced with your UploadChunks collection.
  • Zero-Allocation: Utilizes structural hashing to minimize memory pressure.

Custom Redis Hooks

High-performance chunk tracking to prevent redundant storage writes. 

const engine = new UploadEngine({
  hooks: {
    afterPutObject: async (ctx) => {
      await redis.set(`chunk:${ctx.id}`, 'ready');
    }
  }
});

Media Serving

The serving middleware handles byte-range streaming, MIME resolution from database metadata, ETag generation, and cache headers all in a single mount point.

Middleware Configuration

Property Type Required Description
rootDir string Only for local Physical path to stored files. Only used when storageProvider is 'local'.
database MetadataRepository Yes Resolves file identity, content type, and pipes binary chunks for DB-backed files.
cacheMaxAge string No Cache-Control duration. e.g. '30d', '1h'.
onBeforeServe Function No Called before serving. Throw to deny access (RBAC).
onAfterServe Function No Called after serving. Use for download auditing.
onError Function No Called on serving errors. Pipe to Sentry/Datadog.

Quick Start

Mount the middleware on any path. The framework's routing handles path stripping automatically no redundant prefix configuration needed.

express-serving.ts
import { createExpressFileServingMiddleware } from '@upload-media/server';

// Database-backed serving (MongoDB or SQL)
app.use('/media', createExpressFileServingMiddleware({
  database,
  cacheMaxAge: '30d'
}));

// Local disk serving
app.use('/uploads', createExpressFileServingMiddleware({
  rootDir: './uploads',
  database
}));

Serving Dispatch

The engine dispatches based on the storageProvider field in the file's database record:

storageProvider Behaviour
'local' Streams from rootDir on disk. Requires rootDir in config.
'database' Pipes binary chunks directly from SQL/MongoDB.
's3' / 'cloudinary' / other Issues a 302 redirect to the provider's signed URL.

Service Handlers with Hooks

MongoDB / Mongoose

Serving with access-token validation on every request.

const database = new MongooseRepository({ mongooseConnection: conn });

app.use('/api/assets', createExpressFileServingMiddleware({
  database,
  onBeforeServe: async (fileId, req) => {
    if (!req.headers.authorization) throw new Error('Unauthorized');
  }
}));
SQL (Postgres / MySQL)

Download auditing via serving callbacks.

const database = new SQLRepository({ executor: pg, filesTable: 'media' });

app.use('/cdn', createExpressFileServingMiddleware({
  database,
  onAfterServe: async (file, stats) => {
    await logDownload(file.id, stats.ip);
  }
}));

Method Arguments Description
